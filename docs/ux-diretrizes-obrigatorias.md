# MyASA 2.0 — Diretrizes Obrigatórias para UX e Interface

> Versão: 17/06/2026
> Status: Aprovado — requisito obrigatório do produto

---

## Filosofia Principal

O MyASA não é um sistema administrativo. Não é um ERP. Não é um sistema de RH.

O MyASA é uma ferramenta operacional para equipes artísticas.

O objetivo principal não é registrar informações. É ajudar pessoas a tomar decisões operacionais.

Sempre que existir conflito entre cadastro/formulário/burocracia e tomada de decisão/operação/resolução de problemas — **a operação deve vencer.**

---

## Filosofia do Supervisor

O Supervisor não trabalha preenchendo dados. O Supervisor trabalha:
- Validando
- Analisando
- Decidindo
- Ajustando
- Resolvendo problemas

O sistema deve reduzir trabalho administrativo. O sistema deve aumentar clareza operacional.

---

## Filosofia da IA

A IA não é um chatbot. A IA é um assistente operacional.

A IA deve ajudar o Supervisor a responder:
- O que mudou?
- Qual o impacto?
- Quais são os riscos?
- Quais alternativas existem?
- Qual é a melhor decisão?

A IA deve **explicar**, **justificar** e **apresentar alternativas**. A IA não deve apenas executar.

---

## Mobile First Real

Mobile não é uma adaptação da Web. O Mobile é tão importante quanto a Web.

O Supervisor frequentemente está:
- No backstage
- Próximo ao gelo
- Acompanhando ensaios
- Acompanhando shows
- Caminhando pela operação

**Toda tarefa crítica deve ser possível pelo celular. Nenhuma atividade essencial deve depender exclusivamente da Web.**

---

## Filosofia de Complexidade

A operação é complexa. A interface não deve ser.

O sistema deve esconder complexidade até que ela seja necessária.

Primeiro: resumo, status, problemas.
Depois: detalhes, configurações, edição.

**Nunca o contrário.**

---

## Filosofia dos Livros

Os Livros são o coração do MyASA. Não são formulários. Não são tabelas. Não são cadastros.

Eles representam conhecimento operacional.

O Supervisor deve entender rapidamente:
- Se existe problema
- Onde existe problema
- Qual é o impacto
- Qual é o risco

**A edição é secundária. A compreensão é primária.**

---

## Filosofia da Escala

A Escala não é um cadastro de pessoas. A Escala é uma ferramenta de validação operacional.

A principal pergunta da Escala é: **"A operação está pronta?"**

Não: "Quem está cadastrado?"

---

## Filosofia das Folgas

Folga não é um evento administrativo. Folga é um evento operacional.

Sempre que uma folga for analisada, o sistema deve priorizar **impacto, cobertura, risco e alternativas** — antes de mostrar "aprovar ou negar".

---

## Filosofia das Substituições

O Supervisor não procura pessoas. O Supervisor procura soluções.

O sistema deve apresentar: impacto, risco, alternativas, consequências. **Não apenas nomes.**

---

## Filosofia da Comunicação

O Supervisor não procura enviar mensagens. O Supervisor procura alinhamento operacional.

A pergunta principal não é: "Enviei?"
A pergunta principal é: **"Eles sabem o que precisam fazer?"**

A interface deve priorizar: confirmação, visualização, entendimento, execução.

---

## Sensação de Uso

O usuário deve sentir: **clareza, calma, organização, confiança.**

Mesmo quando a operação estiver caótica.

---

## Identidade Visual

**Inspiração:** iOS, Apple Calendar, Apple Reminders, Apple Health.

**Não inspirado em:** ERP, RH, sistemas corporativos, sistemas administrativos antigos.

**Visual:**
- Modo claro como padrão
- Muito espaço em branco
- Cards arredondados
- Glassmorphism leve
- Poucas cores
- Poucos elementos visuais competindo

---

## Marca

A asa do MyASA é o principal elemento visual.

Versões: Asa Glass, Asa Outline, Asa Marca-d'água.

Nunca utilizar o antigo fundo escuro do ícone dentro da interface.

Referência: `docs/myasa-asa-logo.png`

## Framework Obrigatório para Análise de Descobertas

Toda descoberta da entrevista ou pesquisa deve ser analisada com os 6 pontos:

1. **Resposta Operacional** — o que acontece na operação real
2. **Impacto Operacional** — o que essa realidade afeta na operação
3. **Impacto para UX** — o que isso muda na experiência
4. **Impacto para Interface** — o que isso muda na tela/componente
5. **Riscos** — o que pode dar errado se o sistema ignorar isso
6. **Oportunidades para IA** — onde a IA pode ajudar neste ponto
