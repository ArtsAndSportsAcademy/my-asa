# MyASA 2.0 — Sprint 1: Auth + Organização Base

Utilizar obrigatoriamente:

* Arquitetura Técnica MyASA 2.0
* Sprint 0 entregue
* Blueprint Executivo
* Gate Final de Construção
* Backlog Mestre
* Schema v1 aplicado
* Seed de demonstração

Objetivo:

Construir a base real de acesso e organização para o MVP piloto.

Não criar novas funcionalidades.

Não alterar arquitetura.

Não criar telas fora do escopo.

═══════════════════════
PARTE 1 — BACKEND AUTH
═══════════════════════

Criar:

artifacts/api-server/src/routes/auth.ts

Endpoints obrigatórios:

POST /auth/login
POST /auth/logout
GET /auth/me
POST /auth/refresh

Requisitos:

* login por e-mail e senha
* senha com hash seguro
* JWT access token
* refresh token
* sessão revogável
* logs com requestId e correlationId
* SecurityAuditLog para login, logout, falha de login e refresh

Critérios de aceite:

* usuário seed consegue logar
* senha errada retorna erro seguro
* token inválido retorna 401
* logout invalida sessão
* /auth/me retorna usuário + papéis + organização

═══════════════════════
PARTE 2 — GUARDS E PERMISSÕES
═══════════════════════

Implementar guards:

* requireAuth
* requireRole
* requireOrganization
* requireOperationScope

Regras:

Admin vê organização inteira.
Supervisor vê apenas seus grupos/operações.
Membro vê apenas seus próprios dados.

Critérios de aceite:

* Admin acessa endpoints organizacionais
* Supervisor não acessa dados fora do escopo
* Membro não acessa dados de outro membro
